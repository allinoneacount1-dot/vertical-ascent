## 1. Konteks, misi, non-goals

**Konteks.** Owner ingin satu game 3D browser yang terasa seperti *Only Up!* (SCKR Games, 2023): satu jalur vertikal menerus dari tanah ke puncak, tanpa checkpoint, salah lompat berarti kehilangan ketinggian, karakter manusia beranimasi, kamera third-person, zona bertema yang terasa tinggi, HUD ketinggian dan timer, audio yang bereaksi pada gameplay, dan build statis yang bisa dimainkan lokal. Stack wajib: `@react-three/viverse`, React Three Fiber, Three.js, TypeScript, Vite.

**Misi.** Menyerahkan **G5 PASS**, atau `PASS-WITH-GAPS` yang isinya hanya item yang menunggu owner (kelas (a) §5.0). Artinya: `dist/` yang dimainkan dari spawn sampai victory dengan input normal, aset legal lengkap, dokumen dan bukti sesuai §6.

**Non-goals** (tidak dikerjakan, tidak diusulkan, tidak disiapkan "untuk nanti"): mobile/touch; multiplayer; login/avatar/publish VIVERSE; checkpoint dan mode Assist; sistem senjata; fall damage/health; level **acak atau prosedural saat runtime** (generator offline yang menghasilkan data terkomit boleh, D-022); LOD dan preset kualitas; chunk streaming; service worker/PWA; CI pipeline; analytics atau telemetry jaringan; deploy publik. Gamepad hanya opsional di G4.

**Nama.** Codename **Vertical Ascent** dipakai untuk folder, package, dan `<title>`. Codename ini internal: tercatat merek AS "VERTICAL ASCENT" (Landscape Structures Inc., serial 76587407, kelas 028 peralatan panjat taman bermain, live) — risiko rendah karena bukan kelas video game, tetapi nama publik diputuskan owner (OWNER_RUNBOOK Q1). String `Only Up`, `OnlyUp`, `only-up`, `Fortnite`, dan `viverse-logo` tidak muncul di artefak produk: nama folder, `package.json`, `<title>`, meta HTML, HUD/menu, logo, URL, storage key, nama file evidence. Nama package library (`@react-three/viverse`) dan kredit library tidak terkena aturan ini. Komentar kode yang merujuk contoh upstream ditulis `pmndrs-example:<nama>/<path>` (gate string ref/05 mengecualikan baris berpola itu). Satu kalimat nominatif diizinkan hanya di README §Inspiration: *"Inspired by the vertical-climbing genre popularized by Only Up! (SCKR Games, 2023). Not affiliated with or endorsed by its developer or any trademark holder."*

**Arti "terasa seperti Only Up" di dokumen ini**: jalur tunggal menerus; tanpa checkpoint; jatuh tidak melukai dan kamu lanjut dari tempat mendarat; semakin tinggi semakin mahal jatuhnya; zona bertema dengan landmark yang terlihat dari bawah; puncak palsu lalu puncak asli; satu bagian "jebakan" yang ditelegrafkan dekat puncak; angin dan kamera yang membuat ketinggian terasa. Yang tidak ditiru: nama, karakter, narasi, aset, tulisan "Winner", Easter egg ber-IP.

### 2.3 Shell dan proses panjang

- **Setiap perintah pnpm/node/npx/vitexec/git/rg dijalankan lewat Bash tool (Git Bash) dari root project.** PowerShell hanya untuk cmdlet Windows (mis. status baterai). Alasan: PowerShell 5.1 membuang tanda kutip ganda di argumen exe native, tidak mengenal `&&`, dan tidak mengekspansi glob.
- **Tidak ada kode JS inline ke vitexec.** Tulis file di `vitexec/probes/<nama>.ts` dan jalankan by path.
- **Konversi path MSYS**: Git Bash mengubah argumen yang diawali `/` menjadi path Windows (`/sub/` → `C:/Program Files/Git/sub/`) — tanpa error. Argumen semacam itu (pola sparse-checkout, path URL) dioper lewat stdin/heredoc, ditulis tanpa slash di depan, atau perintahnya diawali `MSYS_NO_PATHCONV=1`.
- **ripgrep di Windows** mencetak path dengan backslash, jadi filter `| rg -v "^src/x/"` tidak menyaring apa pun; kecualikan folder dengan glob (`-g '!src/x/**'`). Gate "harus 0 hit" ditulis `! rg …` (rg exit 1 bila tidak menemukan apa pun).
- **Run vitexec yang diperkirakan >90 s**: Bash `run_in_background: true`, `--timeout` eksplisit ≈2× durasi yang diperkirakan, dan `set -o pipefail; … 2>&1 | tee <log>`. Tunggu notifikasi selesai; jangan polling dengan sleep. Bila Bash tool yang membunuh proses → `NOT-VERIFIED(harness-timeout)`, ulangi di background. Bila `--timeout` vitexec yang terpicu → `FAILED(stalled)` dengan log.
- Server panjang (dev, preview) tidak dijalankan foreground. Dev server untuk mata manusia: `preview_start name=vertical-ascent`. Bila `preview_start` gagal dua kali: jalankan perintah npm yang sama lewat Bash background, arahkan pane ke URL-nya, catat sebagai D-0xx.

## 3. Keputusan D-001 … D-024

Seed ke `docs/DECISIONS.md` di G0 dengan format: judul + ringkasan ≤3 baris + `source: directive §3 D-0xx`. Entri baru mulai D-025 dengan format 4 bagian (konteks / pilihan / bukti file:baris atau URL / konsekuensi), ≤10 baris. Keputusan hanya berubah lewat entri baru yang mengutip bukti.

**D-001 — Controller hybrid.** Komposisi: `useCharacterModelLoader` + physics vendored (D-002) + fungsi velocity, sprint, dan jump milik game + `CharacterCameraBehavior` yang di-instansiasi langsung (D-014) + graf animasi `CharacterModelProvider`/`CharacterAnimationAction` (`@react-three/timeline`). Ini bentuk `pmndrs-example:fortnite/src/app.tsx` tanpa lapisan shooter dan tanpa kunci yaw ke kamera. Alasan: `<SimpleCharacter>` React menyembunyikan objek physics (`packages/react/src/simple.tsx:53,69`), meng-hard-code wind-up lompat 0.2 s (`:189`) dan landing 150 ms (`:264`), dan binding default-nya dibuat ulang di setiap render (`utils.ts:119-143`). Setiap objek atau fungsi yang dioper ke loader model/animasi (`boneMap`, `boneRotationOffset`, `mask`, `trimTime`) adalah **konstanta level modul** di `src/character/rig.ts`; objek inline memicu loop Suspense tanpa akhir (loader memakai `suspend()` dengan perbandingan `===`). Urutan frame dan pemilik setiap besaran: ref/02 §Frame order dan §Pemilik.

**D-002 — Physics vendored.** Salin `packages/viverse/src/physics/index.ts` (MIT, 186 baris) dari clone upstream ke `src/physics/character-physics.ts` di balik `CharacterPhysicsPort`. Checklist lengkap di ref/04 §Vendoring; intinya: `updatesPerSecond: 240`; `jump(speed)` yang **menyetel** `vy = speed` (impulse aditif membuat lompatan coyote hanya setengah tinggi); `isGroundedRaw` (kontak di step ini) terpisah dari `canJump` (`notGroundedSeconds < coyoteTime`, 0.12 s); `resetVelocity()`, `teleport(p)`, `applyCarry(delta)`; `forceWriteBack` untuk step dengan carry **atau** saat AABB kapsul bersinggungan dengan AABB body kinematic mana pun (+0.1 m); panggilan `world.updateSensors(...)` di akhir `update()` **wajib dipertahankan** (tanpanya `BvhPhysicsSensor` tidak pernah terpicu); melempar error bila `model.parent == null`. Header MIT di file, konversi TS untuk `erasableSyntaxOnly`/`verbatimModuleSyntax`, import `BvhPhysicsWorld` dari `@pmndrs/viverse`. Pintu darurat (setelah ≤1 hari fokus, bila TEST-11a/31/34 tetap gagal): `@react-three/rapier` `KinematicCharacterController` di balik port yang sama, sebagai keputusan baru.

**D-003 — Provider `<BvhPhysicsWorld>`, tanpa `<Viverse>`.** Tanpa `clientId`, `.env.production`, `@viverse/cli`, atau hook `useViverse*`; `useCharacterModelLoader({ useViverseAvatar: false, … })`. `@viverse/sdk` berlisensi proprietary dan melarang redistribusi. Smoke build 2026-10-29: SDK dan `@react-three/xr` ter-tree-shake keluar dari `dist/` bila hanya `BvhPhysicsWorld` dan hook yang dipakai. Gate G0 dan G5: `! rg -l "viverse\.com|sdk-api|htcvive" dist/assets` (exit 0 = lulus). Bila tidak kosong → `BLOCKED(viverse-sdk-in-bundle)`: cari modul pengimpor dan hapus; hanya bila tak terhindarkan, alias `@viverse/sdk` ke stub lokal sebagai keputusan baru.

**D-004 — Input dan pointer lock.** `useKeyboardLocomotionActionBindings({ requiresPointerLock: true })` + `usePointerLockRotateZoomActionBindings({ lockOnClick: false })`, keduanya di-mount sekali di root Canvas. **Satu jalur masuk PLAYING**: `enterPlaying()` dipanggil dari handler klik Play, Continue, New climb, Resume, Restart (setelah konfirmasi), Replay, Free roam, dan resume setelah context restore; ia memanggil `canvas.requestPointerLock({ unadjustedMovement: settings.rawInput })` (default `true`; fallback tanpa opsi pada `NotSupportedError`) dan state baru menjadi PLAYING **hanya** setelah `pointerlockchange → canvas`. Pada `NotAllowedError`/`SecurityError`: tetap di layar saat ini dengan hint "Click again", tanpa retry otomatis. `requiresPointerLock` tidak menahan `JumpAction` (EventAction, `action/keyboard.ts:80-90`), jadi controller mengabaikan jump kecuali `state === 'PLAYING' && document.pointerLockElement === canvas`, dan mengosongkan buffer jump di setiap transisi masuk PLAYING. Setelah menu apa pun ditutup: `canvas.focus()` (binding keyboard mendengar di canvas). `contextmenu` di canvas di-`preventDefault`; `Space` saat target `<button>` di PLAYING di-`preventDefault`; elemen HUD non-interaktif `tabIndex={-1}`. Tidak memakai `useSimpleCharacterActionBindings`, `useScreenButton` (men-set className canvas menjadi `mobile-only`), atau binding layar.

**D-005 — UI React DOM.** Tanpa `@react-three/uikit`. Nilai HUD lewat store zustand yang diperbarui ≤10 Hz dari `useFrame` (atau tulis DOM langsung); subtree controller tidak menerima prop yang berubah selama bermain. `<Canvas>` tidak pernah di-unmount antara menu dan game. StrictMode dipertahankan.

**D-006 — State machine.** `LOADING | ERROR | MENU | PLAYING | PAUSED | VICTORY`, plus `mode: 'run' | 'freeRoam'`. *Falling* adalah flag karakter (`airborne`, `bigFall`), bukan state. Physics, sensor, world clock, dan timer hanya maju di PLAYING, dan PLAYING mensyaratkan `worldReady` (D-013). Di G1, MENU = layar Click-to-Play dengan satu tombol Play. Tabel transisi lengkap: ref/02 §State table.

**D-007 — Jatuh, kill plane, restart.** Tanpa damage. Mendarat di mana pun = lanjut dari situ. Koordinat: 1 unit = 1 m, +Y ke atas, pivot karakter di kaki, kaki spawn di `(0,0,0)`. Z1 punya lantai nyata seluas `floorAABB` = AABB footprint rute ±120 m (dihitung dari data level). Kill plane: `y < -20` **atau** posisi horizontal di luar `floorAABB` yang diperluas 10 m; hanya tercapai lewat bug. Respawn kill plane: fade 300 ms → `port.teleport(spawn)` + `resetVelocity()` → **run yang sama** (timer lanjut, `run.killPlaneRespawns++`, best height tetap), toast "Fell out of the world". Restart (hanya dari pause menu, dengan konfirmasi "Restart from the ground? Your current height will be lost.") = **run baru**: timer 0, height 0, `records.restartCount++`, world clock ke t0, kamera menghadap rute. Saat spawn pertama, kamera menghadap pad rute pertama.

**D-008 — Timer, ketinggian, rekor.** Height HUD = `floor(feet.y - spawn.y)` m, tidak pernah negatif, format `127 / 180 m` dengan target = `fakeSummitY` sampai puncak palsu pertama kali dicapai, lalu `summitY` (D-022). Timer mulai pada input gerak pertama setelah spawn; berjalan hanya di PLAYING; menjumlahkan delta frame **tanpa skala** (Focus tidak memperlambatnya) yang di-clamp ≤0.1 s; tidak berjalan saat PAUSED/hidden; lanjut melewati respawn kill plane; beku di VICTORY; direset hanya oleh Restart dan New climb. Format HUD `mm:ss`, layar victory `mm:ss.d`. Counter: `run.killPlaneRespawns`, `run.bigFalls`, `run.metersLost`, `records.lifetimeBigFalls`, `records.restartCount`, `records.completions`. `bestTimeMs` ditulis hanya saat VICTORY dalam `mode: 'run'` dan `!run.focusUsed`; `bestHeightM` saat maksimum grounded baru. Skema storage: ref/02 §Storage.

**D-009 — Save-on-quit + Continue (bukan checkpoint).** Genre pembanding (Getting Over It, Jump King, A Difficult Game About Climbing, Chained Together) menyimpan posisi saat keluar sambil menolak checkpoint; ketiadaannya adalah keluhan terbesar Only Up!. `lastSafe` dicatat hanya ketika `isGroundedRaw`, probe carry tidak menemukan platform kinematic, **dan** probe ray mengenai geometri statis dalam 0.1 m. Ditulis ke `va.run.v1` pada `pagehide`, `visibilitychange → hidden`, dan "Save & quit". Restore: `lastSafe + (0, 0.05, 0)`, `resetVelocity()`, verifikasi ray ke bawah mengenai permukaan dalam 0.3 m; bila tidak, spawn + toast. Pause menu punya **"Save & quit to menu"** (run tetap, timer beku), bukan "Return to menu" yang menghapus run. MENU menampilkan **Continue (`<h> m · <mm:ss>`)** bila ada run tersimpan, dan **New climb** (konfirmasi bila ada run tersimpan). Owner boleh mematikan fitur ini (OWNER_RUNBOOK Q3).

**D-010 — Verba gerak.** Walk, sprint, jump dengan busur tetap (tanpa variable jump height). Sprint dimiliki game sebagai `sprintActive`: Hold = `RunAction.get()`; **Toggle (default)** berganti hanya pada rising edge tombol sprint, tanpa timeout diam; Always = selalu true. Fungsi velocity game (salinan proyek `update-input-velocity.ts`) dan graf animasi membaca `sprintActive`, tidak pernah `RunAction` langsung. Glyph sprint kecil di HUD saat aktif dalam mode Toggle/Always. Air control instan bawaan library adalah baseline; momentum udara hanya lewat keputusan baru bila playtest memintanya. Tanpa crouch/roll/mantle/ledge-grab. **Focus** (opsional G4): tahan RMB → `timeScale 0.5` selama ≤2 s, recharge 10 s, meter terlihat; dilepas otomatis pada blur, `visibilitychange`, kehilangan pointer lock, dan PAUSED; menskala dt physics, world clock, dan `mixer.timeScale`, tidak menskala input kamera, UI, atau run timer; memakai Focus sekali saja menyetel `run.focusUsed = true`, dan run itu tidak mencatat PB (run "Pure" = tanpa Focus).

**D-011 — Stepping physics.** `updatesPerSecond: 240` eksplisit: substep library jadi ≤1/240 s di frame rate apa pun, sehingga toleransi TEST-31 tercapai tanpa stepper kedua (replika 2026-10-29: Δapex 0.0022 m, ΔXZ 0.0095 m; pada 60 Hz Δapex 0.033 m dan ΔXZ 0.10 m — gagal). Di sisi app: clamp delta ≤0.1 s, physics dilewati saat PAUSED, delta pertama setelah resume dibuang. Platform kinematic tidak di-substep oleh library, maka **frame dipecah**: bila perpindahan platform terbesar dalam frame >0.2 m, frame dibagi menjadi `n = ceil(disp / 0.2)` irisan; tiap irisan memajukan world clock, matriks platform, carry, lalu `step(dt/n)`. Timer buffer, coyote, dan re-jump memakai **waktu simulasi**: controller berlangganan `JumpAction` dan mencap tekanan dengan `simTime`; tidak pernah memakai `JumpAction.getLatestTime()` atau `shouldJump()` (keduanya `performance.now()`). Run timer mengikuti D-008. Saat PAUSED: `model.mixer.timeScale = 0`, dikembalikan saat resume. Bila TEST-31 tetap gagal pada 240: accumulator fixed-step + interpolasi posisi render sebagai keputusan baru. Angka gerak (apex, airtime, jangkauan) **diukur**, bukan dihitung (ref/03 §Movement).

**D-012 — Platform bergerak dan carry dibangun di game.** `kinematic` hanya membuat tabrakan mengikuti `matrixWorld` saat query; library tidak membawa karakter, tidak tahu body yang diinjak, dan melewati penulisan posisi saat grounded+idle (`physics/index.ts:111-113`). Maintainer (issue #3): "you cannot yet properly stand on kinematic objects as you wont move with them". Resep wajib: ref/04 §Carry — yang bergerak adalah grup **di atas** `BvhPhysicsBody kinematic`, bukan anak di dalamnya; probe 5 ray terhadap pose sebelumnya; Δ diteruskan ke `port.applyCarry()`. Platform berputar yang **diinjak** hanya dibuat bila level membutuhkannya, dan setelah TEST-11b lulus. Obstacle berputar (palang penyapu) boleh sejak G2: kecepatan permukaan ≤8 m/s, tebal ≥0.5 m, clearance jalur sapuan ≥2.0 m vertikal dan ≥1.1 m horizontal dari collider statis. Semua fase gerak berasal dari satu world clock waktu-simulasi.

**D-013 — Geometri tabrakan.** Collider adalah box yang **dibangkitkan dari data level** (ref/03 §Data level), terpisah dari visual. GLB visual berada di luar semua `BvhPhysicsBody`. Tidak pernah mengubah `visible` objek di bawah body atau sensor; toggle debug hanya mengubah `material.visible`. Solid tertutup tebal ≥0.5 m; tanpa collider bidang tunggal; tangga visual non-collider + ramp collider ≤40°; `maxGroundSlope: 1.0` eksplisit (dokumen library bilang 0.5, kode `?? 1`). Tidak ada `InstancedMesh`/`BatchedMesh` di dalam body mana pun (`removeBody` tidak membersihkan entri instanced; StrictMode dev me-mount ulang). `<WorldReady/>` dirender setelah semua body zona di dalam boundary Suspense yang sama dan menyetel `worldReady`. **D-014 — Kamera.** `new CharacterCameraBehavior()` (di-re-export oleh `@react-three/viverse`) di `useMemo`, di-dispose saat unmount, `update(camera, target, dt, camRaycast, opts)` di `useFrame(-1)`; hook `useCharacterCameraBehavior` tidak dipakai (raycast-nya terkunci ke `world.raycast`). `camRaycast`: ray tengah + 4 whisker (±0.25 m) terhadap world kamera kedua (`Vanilla.BvhPhysicsWorld`) yang hanya berisi hull pemblokir per zona (tanpa railing, kabel, pipa tipis); ambil hit terpendek; snap-in langsung, ease-out τ = 0.15 s; kembalikan `max(s, 0.55)` sehingga jarak setelah offset 0.2 tetap ≥0.35. ## 5. Gate G1–G5

### 5.0 Semantik gate

- Urutan kerja = urutan gate. Di dalam gate, bila dua tugas bersaing, yang menang: playability → kebenaran physics → kelengkapan rute → legalitas aset → kualitas aset → polish visual → performa.
- **PASS** = setiap TEST yang kolom Gate-nya (§7) memuat gate ini berstatus `VERIFIED-PASS` atau `N/A(<D-id>)` (TEST-38 diagnostik: `IMPLEMENTED` cukup), ditambah butir "Selesai bila" gate.
- **PASS-WITH-GAPS: <ids>** hanya untuk: (a) `BLOCKED` menunggu owner — persetujuan unduhan, aset OWNER-ONLY, dan bagian manual (`BLOCKED(owner-manual)`); (b) placeholder yang tercantum di baris "Placeholder yang diharapkan" gate itu; (c) TEST yang kolom Gate-nya menyebut gate lain. TEST milik gate ini yang `FAILED` atau `NOT-VERIFIED` membuat gate **FAIL** → §2.6 (akhiri giliran, satu pertanyaan).
- Evidence sebuah TEST masuk folder gate sesi yang sedang berjalan (`evidence/G<n>/`).
- Setiap gap disalin ke "Blocked / needs owner" di PROGRESS dan menjadi tindakan pertama gate berikutnya.

## 6. Evidence

- Folder `evidence/G<n>/TEST-<id>-<slug>.<log|json|png|mp4|har>`; `evidence/G<n>/<timestamp>/` boleh untuk rerun yang butuh riwayat. Setiap baris TEST di PROGRESS memuat status, path artefak, perintah persis, hash commit, tanggal.
- Artefak hanya dari vitexec, script, atau perintah shell. Screenshot pane browser bukan evidence.
- Screenshot hanya membuktikan render. Mekanik dibuktikan oleh perubahan state yang di-log **plus** perubahan visual di region screenshot tempat mekanik itu terjadi.
- Minimum per lapisan: statis → `build.log`/`typecheck.log`; unit → log vitest; physics → JSON angka; smoke → log + screenshot; rute → `.mp4` + `milestones.json` + screenshot tiap masuk zona + dump state akhir; manual → kutipan kata owner atau "not performed".
- Rekaman vitexec berformat AV1+Opus MP4; bila pemutar owner tidak bisa membukanya, buka di browser atau `ffmpeg -i in.mp4 -c:v libx264 -crf 23 out-h264.mp4`.
- `.mp4`, `.har`, heap snapshot, dan cpuprofile di-gitignore; `evidence/INDEX.md` (path, sha256, TEST-id) dikomit.
